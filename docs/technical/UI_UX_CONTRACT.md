## 2. 입력 자료 해석

### 2.1 스크린샷의 역할

제공된 세 장은 와이어프레임의 **정보와 대략적 배치 참고**이며 픽셀 단위 복제 대상이 아니다.

| 참고 화면               | 유지할 의미                                                       | 활성 해석                                                          |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| 스크린샷 #1             | 좌측 목표·자금·첩보, 중앙 맵·경보, 우측 요원 현황, 상단 단계·시간 | 실제 HUD에서는 맵을 가리지 않도록 레일·드로어·짧은 토스트로 재구성 |
| 도착 공작 메뉴 참고      | 이동 비용과 도착 후 `조사 / 암살 / 해킹` 선택                     | **지도에서 도착지를 탭한 직후** 그 도착지에 표시되는 공작 메뉴     |
| 1차 명령 메뉴 참고       | `이동 / 대기 / 심문 / 숙청` 선택                                  | **요원을 처음 터치한 직후** 그 요원에 표시되는 1차 명령 메뉴       |

사용자는 사진 번호를 잘못 설명했음을 확인하고 메뉴 의미를 우선한 해석이 맞다고 승인했다. 따라서 **요원 선택 → 1차 명령 → 이동 범위 → 지도 목적지 직접 선택 → 빨간 대표 경로 + 도착 공작**으로 확정한다. 스크린샷의 색, 크기와 직사각형 위치는 픽셀 복사가 아니라 첫 fixture UI의 유사한 정보 배치·형태 기준으로 사용한다.

입력 파일 식별값은 다음과 같다. 저장소에는 바이너리를 복제하지 않고 이 계약과 hash로 참고 입력을 식별한다.

| 입력                             | SHA-256                                                            |
| -------------------------------- | ------------------------------------------------------------------ |
| `스크린샷 2026-08-18 205409.png` | `1358534D61E805D82001F34185F9F6C0140DAEFAE723A49BDB34CB3B4844A590` |
| `스크린샷 2026-08-18 205418.png` | `CC04C94B972068CE8C7CEADD40B3FDA8D1B2119CB19F018CDCEA1309F8F1E709` |
| `스크린샷 2026-08-18 205414.png` | `CA823A692A42C15C4AEDD2015488B24016B243F2B72F26B595D0132F5CBC39B6` |

### 2.2 제품 인상

프로토타입 화면 작업명은 `PROJECT SPY`를 사용한다. 이는 기획 문서 내부 가제 `THE MOLE`을 최종 제품명으로 변경하거나 Q-001을 해결한다는 뜻이 아니다.

- 가까운 미래의 정보 작전 지휘실
- 냉정하고 읽기 쉬운 작전 도구
- 화려한 사이버펑크보다 제한된 정보와 선택의 긴장
- 장식보다 상태·비용·위험·확정 여부가 먼저 보이는 화면
- 일반적인 SaaS 대시보드나 마케팅 랜딩 페이지처럼 보이지 않는 게임 UI

## 3. 목표 기기와 뷰포트 계약

### 3.1 우선 기기 해석

사용자는 목표 기기가 **Samsung Galaxy Tab S9+**임을 확인했다. 알려진 물리 패널 크기나 해상도를 CSS 레이아웃 수치로 직접 사용하지 않는다. Android Chrome의 주소창, 시스템 바, 화면 확대, 멀티윈도와 DPR에 따라 실제 CSS 뷰포트가 달라지기 때문이다.

다음 정보는 첫 실기기 점검 때 기록한다.

- 정확한 모델 코드
- Android 및 Chrome 버전
- 가로의 `innerWidth × innerHeight`와 `devicePixelRatio`, 세로에서 orientation gate가 활성화되는지
- 브라우저 전체화면, 일반 탭, 멀티윈도 각각의 사용 가능 영역
- 터치·S Pen·키보드·마우스 연결 여부
- 안전 영역 inset과 가상 키보드 노출 시 뷰포트 변화
- 기본 품질에서의 프레임 시간과 메모리 경향

이 실측은 물리 태블릿 통과 선언과 최종 성능 튜닝에는 필요하지만 현재 Phase 0B 구현을 막지는 않는다.

### 3.2 방향과 크기 등급

- **게임은 가로 전용**이다. 유효한 gameplay viewport는 `width > height`를 만족해야 한다.
- 세로에서는 Canvas·HUD·명령 입력을 비활성화하고 `가로 화면으로 회전해 주세요` orientation gate만 표시한다.
- 세로 화면을 CSS `transform`으로 90도 돌리거나 portrait용 gameplay reflow를 만들지 않는다.
- 방향이 다시 가로가 되면 fixture 또는 허용된 클라이언트 상태를 잃지 않고 같은 화면으로 복귀한다.
- 유효한 가로 화면 안에서는 하드웨어 모델명이 아니라 CSS 컨테이너 너비로 레이아웃을 결정한다.

| 등급    |    CSS 너비 | 기본 구성                                                           |
| ------- | ----------: | ------------------------------------------------------------------- |
| Wide    | 1200px 이상 | 전체 화면 맵 위 좌측 218–272px / 우측 244–304px 반투명 고정 레일     |
| Tablet  |  900–1199px | PC와 같은 양쪽 고정 레일을 유지하되 좌 210–235px / 우 236–260px 사용 |
| Compact |   600–899px | 상단 상태 바 + 전체 맵 + 하단 명령 시트, 목표·요원은 드로어         |
| Narrow  |  599px 이하 | 한 열 로비·목록과 전체 폭 하단 시트; 3D와 동등한 DOM 명령 목록 제공 |

위 크기 등급은 orientation gate를 통과한 가로 viewport에만 적용한다. 높이가 600px 미만이면 상단 상태 바와 카드 간격을 압축하고 패널 본문만 독립 스크롤한다. 맵 자체를 페이지 세로 스크롤 안에 넣지 않는다.

### 3.3 뷰포트와 안전 영역

- 앱 셸은 `100dvh`를 우선 사용하고, 지원하지 않는 환경에는 `100svh`와 `100vh` 순서의 폴백을 둔다.
- `env(safe-area-inset-*)`를 반영한다.
- 가상 키보드가 열린 로비는 활성 필드를 보이게 스크롤하되 게임 카메라를 움직이지 않는다.
- 브라우저 확대 200%에서도 핵심 명령이 잘리거나 겹치지 않아야 한다.
- 확대·멀티윈도에서는 컨테이너 크기에 맞는 등급으로 재배치한다.
- 멀티윈도나 가상 키보드 때문에 `width <= height`가 되면 gameplay reflow 대신 orientation gate로 전환한다.

### 4.2 글꼴

Korean-first 폰트 스택은 다음과 같이 고정한다.

1. UI와 본문: `"Geist Sans", "Pretendard Variable", Pretendard, system-ui, sans-serif`
2. 작전 식별자, 좌표, 시간, 금액, 상태 ID: `"Geist Mono", "Pretendard Variable", ui-monospace, monospace`
3. Geist에 없는 한글 글리프는 Pretendard Variable이 담당한다.
4. 한글을 Geist Mono에 강제로 합성하거나 모든 한글을 고정폭처럼 보이게 하지 않는다.
5. 개발 시 자체 호스팅 또는 빌드 번들을 사용하고 외부 CDN 장애에 의존하지 않는다.

### 4.3 형태, 공간과 움직임

- 기본 4px 그리드, 주요 간격 8 / 12 / 16 / 24 / 32px
- 기본 모서리 4px, 작전 패널·시트 최대 6px, 태그 2px
- 기본 경계 1px, 선택·포커스 2px
- 핵심 버튼의 최소 시각 높이와 터치 영역 48px, 인접 터치 대상 간격 8px
- 즉시 피드백 80ms, 빠른 전환 140ms, 패널 220ms, 화면 전환 320ms
- 경고는 한 번만 강조하고 화면 전체를 흔들지 않는다.
- `prefers-reduced-motion: reduce`에서는 이동·확대 보간을 제거한다.
- 마지막 5초는 색·텍스트·허용된 한 번의 진동으로 알리되 무한 점멸하지 않는다.

## 6. 로비

### 6.1 진입 화면

진입 화면은 마케팅 페이지가 아니라 작전 접속 터미널처럼 구성한다.

- 좌상단: 작업명 `PROJECT SPY`와 소형 버전
- 중앙: 호출명, `방 만들기`, `방 참가`
- 참가 선택 시 초대 링크를 열거나 링크에서 전달된 원문 초대 토큰을 붙여넣는 입력. MVP는 별도 짧은 방 코드를 만들지 않음. 자동 링크는 fragment만 사용하며 client가 token을 memory에 포착한 즉시 `history.replaceState`로 주소에서 제거함
- `진행 중 작전 복구`: 현재 anonymous session에 결합된 waiting·setup·active 방의 안전한 목록
- 하단: 네트워크 상태, 세션 안내, 설정
- 배경: 저채도 도시 실루엣 또는 정적 격자. 자동 재생 영상 없음
- 마지막 호출명은 로컬 편의값일 뿐 인증·권한 근거가 아님

검증 오류는 필드 바로 아래에 설명한다. 제출 중 중복 요청을 막되 뒤로가기와 연결 취소는 유지한다.

### 6.2 대기실

핵심 정보 순서:

1. 비밀이 아닌 opaque 작전 식별자와 `초대 링크 복사`, server time 기준 `유효 59:32`
2. BLUE/RED가 아닌 `국장 A / 국장 B` 플레이어 슬롯
3. 내 상태 `참가 완료`
4. 상대 상태 `초대 대기 / 참가 완료`
5. `2인 · 동시 명령 50초 · 배신자 명령 10초`
6. waiting host의 `초대 링크 재발급`·`방 취소`, 두 player setup의 `작전 취소`

별도 `준비 완료` 토글은 두지 않는다. 두 번째 플레이어 참가가 원자적으로 확정되면 서버가 초기화를 시작한다. 팀은 서버가 게임 초기화 시 동등한 50/50 방식으로 배정하며, 방 생성자에게 진영 선택권이나 선공 이점을 주지 않는다. Presence·heartbeat를 쓰지 않으므로 상대의 `온라인/재접속 중`을 추정해 표시하지 않는다. `재연결 중`은 내 브라우저의 로컬 네트워크 상태에만 쓴다.

초대 링크는 발급 뒤 60분 유효하며 host 화면에서 `inviteExpiresAt`과 `serverTime`으로 남은 시간을 계산한다. 10분 이하에는 `곧 만료 · 링크 재발급`을 표시하고, 만료되면 방은 유지한 채 복사 버튼을 비활성화하고 `새 초대 링크 발급`을 1차 행동으로 둔다. client clock만으로 만료를 확정하지 않는다. 원문 token은 현재 페이지 memory에서만 복사하며 persistent browser storage에 보관하지 않는다. 생성 응답을 잃거나 원문을 받은 뒤 새로고침·탭 복구하면 game ID와 active/expired·expiry만 복구하고 `기존 링크 다시 표시 불가 · 새 링크 발급`을 안내한다. 같은 idempotency key 재시도의 public wire는 `rawInviteTokenIncluded: false`, `inviteRecoveryAction: "rotate"`다. 로컬 key까지 잃으면 `진행 중 작전 복구`에서 자기 waiting 방을 찾은 뒤 새 key로 링크를 재발급한다. 재발급도 응답을 잃으면 또 다른 새 key로 재발급하며 잃은 원문 token을 DB·로그에서 복구하려 하지 않는다. waiting `방 취소`와 첫 일반 명령 전 `작전 취소`는 확인 modal 뒤 서버 cancelled 상태로 전환한다. cancelled membership은 양 사용자의 새 방을 막지 않는다. `active` 게임의 `나가기`는 로컬 화면 이탈만 뜻하며 slot 삭제·기권으로 오해시키지 않는다.

### 6.3 시작 준비

두 번째 플레이어 참가가 확정되면 서버가 맵·시설·진영·배신자와 공개 가능한 초기 상태를 만든다. 허위 진행률 대신 `세션 잠금 / 도시 배치 생성 / 배치 검증 / 비공개 작전 자료 준비 / 요원 명단 은닉 대기`의 이산 상태를 표시한다. 오류는 같은 idempotency key로 재시도해 중복 게임을 만들지 않는다. 진영 배정 후에는 `당신은 BLUE 국장입니다`처럼 텍스트와 팀색을 함께 보여 준다.

## 7. 게임 전 요원 명단 배치

이 단계는 v0.7의 필수 규칙이며 첫 일반 명령보다 먼저 실행한다.

### 7.1 화면

- 같은 북쪽 고정 카메라로 도시를 보이되 호텔 5곳과 지하철역 5곳을 초록색으로 깜빡이게 강조한다.
- 제목: `자기 팀 요원 명단 은닉`
- 안내: `10개 후보 중 한 곳을 선택하십시오. 상대의 선택은 보이지 않습니다.`
- 별도 후보 팝업이나 카드 격자를 띄우지 않는다. 플레이어는 강조된 지도 건물을 직접 눌러 선택한다.
- 키보드·보조기술용 DOM 목록은 지도 입력의 동등 경로로 제공하되 별도 시각 후보 팝업처럼 사용하지 않는다.
- 공개 시설명과 셀 좌표를 함께 표시한다.
- 선택 시 건물 윤곽과 확인 패널만 보이고 경로는 만들지 않는다.
- `이 위치에 은닉`의 서버 응답을 받은 뒤 잠근다.
- 첫 일반 명령이 열리기 전에는 어느 player나 `작전 취소`를 선택할 수 있다. 상대 미응답 때문에 무제한 setup에 갇히지 않도록 하며, 취소는 양쪽 모두에게 적용됨을 확인 modal에 명시한다.

### 7.2 비공개와 충돌

- 상대 위치, 커서, 선택 시각을 노출하지 않는다.
- 내가 잠그기 전 상대 잠금 여부도 보이지 않는다.
- 내 잠금 뒤에는 `상대 선택 대기`만 보이고 정확한 시각은 표시하지 않는다.
- 같은 건물 인스턴스를 골랐다면 서버가 두 선택 모두 무효화한다.
- `같은 위치가 선택되었습니다. 양측이 다시 선택합니다.`만 보여 주며 상대 위치는 공개하지 않는다.
- 기존 선택 강조를 제거하고 새 제출 버전으로 다시 선택한다.
- 시간 제한은 없다. 재접속 시 내 제출 상태만 복원한다.
- 서로 다른 위치가 확정되면 내 은닉 위치만 개인 브리핑에 남기고 첫 일반 명령으로 전환한다.

## 8. 인게임 셸과 HUD

### 8.1 고정 영역

| 영역           | 내용                                         |
| -------------- | -------------------------------------------- |
| 상단 작전 바   | 턴, 단계, 남은 시간, 내 진영, 연결·저장 상태 |
| 좌측 임무 레일 | 3개 목표, 확보·운반, 활동비·은행, 활성 첩보  |
| 배경 전체      | 16×16 3D 도시, 요원, 공개 목표, 선택·경로    |
| 우측 요원 레일 | 자기 요원 3명과 통제 배신자 1명의 상태·초안·실시간 결과 |
| 명령 시트      | 선택 요원의 명령, 경로, 공작, 경고·확정      |

지도는 gameplay viewport 전체를 사용하고 상단 바·좌우 rail·명령 패널을 지도 위 반투명 overlay로 올린다. 900px 이상 Tablet에서는 PC와 같은 좌우 rail과 정보량을 유지하며 카드나 설명을 과도하게 축약하지 않는다. Compact/Narrow에서만 상단 `임무`·`요원` 버튼이 드로어를 열고 명령 작성기는 하단 시트로 유지한다.

상시 UI는 현재 판단에 필요한 턴·단계·자금·목표·요원·최근 결과만 남긴다. 개발 단계명, fixture 상태, 의미 없는 영문 eyebrow, 같은 뜻의 반복 설명은 기본 화면에서 제거한다. 지도 pan·zoom이 시작되면 상단 바·rail·명령·목적지 DOM panel 등 비필수 overlay를 opacity `0.09`로 낮추고 입력을 지도에 양보한다. 조작 종료 420ms 뒤 복귀한다. 세로 gate와 치명적 오류·확인 modal은 이 투명화 대상이 아니다.

### 8.2 항상 보여야 하는 정보

- 현재 단계와 남은 시간
- 명령이 없는 자기 요원 수
- 현재 사용 가능 총액과 작성 중 총비용
- 선택 중 요원, 도착지, 행동
- 연결·저장·잠금 상태
- 도청 노출, 시간 5초 이하, 예산 초과, 숙청 경고

장문 설명과 과거 결과는 보조 패널에 둔다. 큰 영구 경고 상자로 맵을 가리지 않는다.

### 8.3 요원 카드와 상대 정보

자기 요원 카드는 호출부호와 유형, 현재 셀, 생존·충원, 목표 운반, 심문 표식, `P3 → P6 · 조사 · $1,600` 형식의 초안, 저장 상태, 전문 보정을 표시한다. 통제 중인 상대 팀 배신자도 별도의 배신자 카드로 항상 함께 표시한다. 명령 수행 중에는 각 카드가 해당 요원의 현재 동작과 성공·실패를 실시간으로 표시하고, 재생 뒤 5초 동안 최종 결과를 유지한다. 다음 일반 명령으로 넘어가면 이전 턴 결과를 한 줄로 유지한다.

상대 요원은 해당 플레이어에게 합법적으로 공개된 최종 위치와 공개 가능한 목표 운반 상태만 렌더링한다. 유형, 경로, 명령, 내부 확률, 배신 여부를 빈 데이터나 흐린 텍스트로도 암시하지 않는다.

### 8.4 상태와 경보

- 상단 토스트 최대 2개, 기본 4초 후 접기
- 중앙 하단 최근 보고는 평상시 숨기며 도청·재매수·제거·목표 획득·치명적 실패처럼 중요 내용이 있을 때만 표시
- 전체 보고서는 시간순이며 성공·실패·정보·위험 필터 제공
- 서버의 플레이어별 결과 코드와 공개 가능한 인자만으로 문구 조합
- 숨은 값을 일반 이벤트 객체에 넣고 CSS로 숨기지 않음
- 중요 사건 `aria-live="polite"`, 마지막 시간 경고와 단계 종료는 `assertive` 한 번만 사용
- 별도 결과 팝업, 사건별 `이전/다음/전체 보기` 리플레이와 하단 사건 바는 사용하지 않는다. 이미 수신자별로 투영된 실행 cue와 카드 결과만 재생·표시한다.

## 9. 3D 도시와 카메라

### 9.1 시점

- 전역 북쪽이 화면 위를 향하는 **고정 3/4 원근 시점**을 사용한다.
- 자유 회전과 궤도 회전은 첫 구현에서 제공하지 않는다.
- 북쪽 표시와 `시점 초기화`를 항상 제공한다.
- 줌과 제한된 평면 이동만 허용하고 맵 경계를 벗어나 빈 공간만 보이게 하지 않는다.
- 패널이 선택 셀을 가리면 패널 위치를 먼저 바꾸고 필요한 경우에만 맵 중심을 짧게 보정한다.
- 공항·항구와 나머지 특수 건물 이름은 항상 지도에 표시한다. 호텔·지하철역 이름은 hover 또는 터치로 확인하며 hover를 유일한 입력으로 만들지 않는다.

### 9.2 입력 매핑

| 동작               | 터치·S Pen       | 마우스                    | 키보드                   |
| ------------------ | ---------------- | ------------------------- | ------------------------ |
| 요원·셀 선택       | 한 번 탭         | 좌클릭                    | 목록 탐색 후 Enter/Space |
| 맵 이동            | 한 손가락 드래그 | 좌·우·중클릭 드래그       | `Shift` + 화살표         |
| 확대·축소          | 핀치             | 휠                        | `+` / `-`                |
| 목적지 grid cursor | DOM 셀 목록 탭   | DOM 셀 목록 클릭          | 화살표 후 Enter/Space    |
| 단계 뒤로          | 시트의 `뒤로`    | 시트의 `뒤로`             | Escape                   |
| 시점 초기화        | 버튼             | 버튼                      | R                        |

- 한 손가락 입력은 이동량 10 CSS px 이하, 350ms 이하일 때 탭으로 본다.
- 길게 누르기와 hover는 추가 설명을 줄 수 있지만 유일한 진입 방식이 될 수 없다.
- 메시보다 넓은 논리 셀 hit target을 사용한다.
- DOM 요원 목록과 셀 목록으로 Canvas 정밀 조작 없이도 모든 명령을 만들 수 있어야 한다.

### 9.3 렌더링 경계

3D 장면은 서버가 승인한 논리 셀·경로·공개 상태의 표현이다.

- 요원과 셀은 안정적인 논리 ID를 가진다.
- 월드 좌표나 애니메이션 도착 여부로 게임 상태를 추론하지 않는다.
- 이동 애니메이션은 이미 확정된 서버 결과만 재생한다.
- 클라이언트는 자기 플레이어 projection만 받는다.
- 기본 데모는 단순 도형과 제한된 조명을 쓰고 GLB/glTF 교체는 어댑터 뒤에 둔다.
- 상단·좌우 HUD는 Canvas 밖에 둔다. 1차·도착 명령판은 논리 셀 좌표에 연결한 DOM overlay로 렌더링해 pan·zoom 때 도시와 함께 움직이며, 접힌 Canvas 밖 DOM 요원·목적지 목록은 키보드·렌더링 복구 대체 입력으로 유지한다.

## 10. 일반 명령 작성기

### 10.1 상태 기계

```text
IDLE
  └─ SELECT_AGENT
       └─ PRIMARY_MENU
            ├─ WAIT ────────────────┐
            ├─ INTERROGATE ─────────┤
            ├─ PURGE → WARNING ─────┤
            └─ MOVE                 │
                 └─ REACHABLE_MAP   │
                      └─ DESTINATION + REPRESENTATIVE_PATH
                           └─ ARRIVAL_ACTION
                                ├─ MOVE_ONLY ───┐
                                ├─ INVESTIGATE ─┤
                                ├─ HACK ────────┤
                                └─ ASSASSINATE → TARGET
                                                 │
COMPLETE_AGENT_DRAFT ◀────────────────────────────┘
  └─ SAVE_TO_SERVER → SAVED / RETRY + CLOSE_PANEL
       └─ SELECT_NEXT_AGENT or REVIEW_ALL
            └─ LOCK_ALL → IMMUTABLE
```

뒤로가기는 아직 서버에 저장하지 않은 현재 하위 선택만 한 단계 제거한다. 저장된 초안을 바꾸려면 해당 요원을 다시 선택해 새 완전 초안으로 덮어쓴다. 전체 잠금 후에는 수정이 없다.

공작 종류·대기·심문 또는 숙청 확인의 마지막 선택이 그 요원의 확정 입력이다. 저장 직후 명령판을 닫으며 별도 `패널 닫기` 단계나 완료 화면을 표시하지 않는다.

### 10.2 1차 명령 메뉴

자기 팀의 생존·활동 중 요원을 선택하면 요원 좌표에 붙은 소형 명령판으로 다음 네 개를 표시한다.

| 선택 | 표시               | 결과                                 |
| ---- | ------------------ | ------------------------------------ |
| 이동 | `이동 · 칸당 $200` | 도달 범위와 목적지 선택              |
| 대기 | `대기 · $0`        | 현재 칸 유지, 다른 공작 없음         |
| 심문 | `심문 · $1,000`    | 선택한 자기 요원을 심문              |
| 숙청 | `숙청 · $2,000`    | 경고 확인 후 선택한 자기 요원을 제거 |

비활성 항목은 숨기지 않고 `이번 턴 숙청 1회 사용`, `자금 부족`, `충원 대기 중`, `이미 잠김`처럼 이유를 표시한다. 요원 전환 시 다른 요원의 저장된 초안을 잃지 않는다.

### 10.3 이동 가능 범위

`이동`을 선택하면:

- K/H/D는 모두 0–3칸 후보를 표시한다. 삭제된 F의 4칸 이동 후보는 제공하지 않는다.
- 출발 셀도 `현재 위치에서 공작`을 위한 0칸 목적지로 포함한다.
- 상하좌우 이동만 허용하고 같은 셀 재방문과 출발점 복귀를 금지한다.
- 일반 건물 통과 제한과 공항·항구 예외를 반영한다.
- 현재 공개 정보만 사용하고 숨은 상대 점유를 범위 색으로 암시하지 않는다.
- 수용 인원과 동시 이동 때문에 실행 때 막힐 수 있음을 `도착은 실행 시 다시 판정됩니다`로 설명한다.

도달 불가 셀을 탭해도 가장 가까운 합법 셀로 자동 변경하지 않는다. 공개 조건으로 설명 가능한 이유만 표시한다.

### 10.4 목적지와 기본 경로

도착 셀을 탭하면:

1. 합법 경로 중 칸 수가 가장 짧은 경로를 고른다.
2. 동률이면 서버와 클라이언트가 공유하는 고정 좌표 정렬과 이웃 탐색 순서를 사용한다.
3. 같은 입력은 언제나 같은 경로를 만든다.
4. 빨간 선으로 모든 통과 셀을 표시한다.
5. `3칸 · 이동 $600`처럼 거리와 비용을 즉시 갱신한다.

목적지 탭은 대표 경로를 즉시 선택하고 도착 공작 메뉴를 연다. 이동만을 별도로 설명하는 팝업, `경로 수정`, `이 경로 사용` 확인 단계는 표시하지 않는다. 클라이언트가 만든 대표 경로는 미리보기이자 초안 입력일 뿐이며 서버는 저장·잠금·실행 때 최대 거리, 상하좌우, 재방문, 시설 규칙을 canonical 규칙으로 다시 검증한다.

### 10.5 도착 후 공작 메뉴

지도에서 도착지를 탭한 직후 그 도착지에 붙은 소형 명령판으로 다음을 표시한다.

| 선택   | 추가 비용 | 표시 예            |
| ------ | --------: | ------------------ |
| 이동만 |        $0 | `이동만 · 총 $600` |
| 조사   |    $1,000 | `조사 · 총 $1,600` |
| 암살   |    $2,000 | `암살 · 총 $2,600` |
| 해킹   |    $2,000 | `해킹 · 총 $2,600` |

0칸이면 `현재 위치 유지 · $0`와 합법적인 조사·암살·해킹을 표시한다.

- 조사는 끝점 중심 5×5 윤곽을 미리 보이되 상대 존재를 새로 드러내지 않는다.
- 암살은 명령 시점 현재 위치의 3×3 조건을 충족하고 합법적으로 보이는 상대만 후보로 삼는다. 경로 끝점의 3×3도 보이며 대상 이동으로 실행 조건이 깨질 수 있음을 경고한다.
- 해킹은 끝점이 은행 또는 통신국이고 공개 상태상 사용 가능하며 국장별·턴별 제한과 예산을 만족할 때만 활성화한다.
- 이동만은 다른 공작 없이 경로만 저장한다.
- 이동 실패·차단 시 결합 공작도 취소되고 비용이 환불되지 않는다는 문구를 한 번 명확히 표시한다.

### 10.6 심문과 숙청

심문은 선택한 자기 요원이 대상이며 별도 맵 대상 선택이 없다.

- 비용과 그 턴 다른 행동 불가를 확인한다.
- 저장 후 카드에 `심문 예정`을 표시한다.
- 결과 표식은 해당 플레이어 projection에 있을 때만 보인다.
- 재매수로 표식이 제거되면 개인 사건으로 설명한다.

숙청도 선택한 자기 요원이 대상이다. 확인 전에 비용 $2,000, 제거·충원 대기, 무고하면 다음 한 턴 팀 전체 확률형 공작 -10%p, 목표 드롭 가능성, 전체 잠금 후 취소 불가를 보여 준다. 확인 버튼은 `요원 K 숙청 초안 저장`처럼 대상과 결과를 포함한다. 턴당 1회 제한을 넘으면 이유와 함께 비활성화한다.

### 10.7 예산

상단과 검토 화면은 다음을 분리한다.

- 이번 턴 할당금
- 은행 잔액
- 현재 사용 가능 총액
- 저장된 일반 명령 합계
- 배신자 단계에 남을 수 있는 금액
- 현재 선택을 포함한 예상 잔액

할당금을 먼저 쓰고 부족분을 은행에서 쓰는 순서를 보여 준다. 총액을 넘는 초안은 저장 요청을 보내지 않고 어느 명령 때문에 얼마가 초과됐는지 표시한다. 서버도 제안 요원 명령과 나머지 저장 draft·암시적 `WAIT`를 합친 전체 집합의 총비용·숙청/해킹 횟수·턴별 제한을 transaction에서 다시 검증하며, 거부 시 이전 저장 집합을 유지한다. 비용 미환불 규칙은 전체 검토에서도 확인할 수 있다.

## 11. 초안 저장, 잠금과 50초 시간초과

### 11.1 초기값과 완전 초안

일반 명령 시작 시 모든 활동 요원은 화면에서 `자동 대기` 상태를 가진다. 이는 아직 서버에 저장된 선택이 아니라 시간초과나 수동 잠금 때 빠진 요원을 채우는 UI 기본값이다.

서버에 저장하는 최소 단위는 요원 한 명의 **완전한 명령**이다.

- 경로만 있고 공작이 없거나 암살 대상이 없거나 숙청 경고 미확인 상태는 저장하지 않는다.
- 완전 초안이 되면 개인용 서버 draft endpoint에 즉시 저장한다.
- `저장 중 / 저장됨 · HH:MM:SS / 저장 실패 · 다시 시도`를 표시한다.
- 각 쓰기는 독립 `draft_version`으로 충돌을 검사한다.
- 새 요원 초안 때문에 저장된 전체 명령 집합이 예산·횟수·상호 배타 제한을 위반하면 서버가 저장하지 않으며, UI는 서버의 이전 저장 집합과 거부된 로컬 선택을 분리해 보여 준다.
- 초안 편집은 canonical 게임 revision을 올리거나 상대에게 broadcast하지 않는다.
- 재접속하면 내 비공개 서버 초안만 복원한다.
- 로컬 미완성 선택은 권한 근거가 아니며 새로고침 뒤 폐기할 수 있다.

### 11.2 상대 잠금 정보

편집 중에는 상대의 잠금 여부와 정확한 잠금 시각을 보여 주지 않는다. 내 잠금 후에는 `상대 입력 중` 또는 서버가 단계 전환 직전에 제공하는 `상대 완료 · 판정 대기`만 보여 주며, 그 상태로 자기 명령을 다시 열 수 없다.

### 11.3 수동 잠금

`전체 명령 검토`에는 K/H/D 세 슬롯을 모두 나열하되 제거·충원 대기 슬롯은 상태 전용으로 표시한다. 잠금 payload에는 모든 **활동 가능 요원**만 포함하고 미지정 활동 요원은 `대기 · $0`으로 정규화한다. 활동 가능 요원이 0명이면 서버가 일반 명령 입력을 자동 종료한다. 다음 조건에서만 수동 잠금한다.

- 명령이 현재 projection 기준으로 완전함
- 전체 비용과 턴별 제한 충족
- 마지막 draft 저장 성공 또는 잠금 요청이 최종 완전 payload를 원자적으로 함께 제출
- 연결됨, 현재 단계와 서버 deadline이 유효함

서버 성공 응답 뒤에만 `명령 잠김`으로 표시하고 모든 편집을 읽기 전용으로 바꾼다. 자기 비밀 lock 응답의 `privateInputScope`·`privateInputVersion`은 shared game revision과 별도로 적용해, revision이 같더라도 더 최신 owner 응답을 버리지 않는다.

### 11.4 시간초과

- 서버 기준 50초이며 클라이언트 시계는 권한이 아니다.
- deadline에서 마지막 저장 완전 초안을 스냅샷한다.
- 초안 없는 활동 요원은 `대기`로 채운다.
- 저장되지 않은 UI 중간 선택은 버린다.
- `시간 초과 · 저장된 1개 명령 + 자동 대기 2개`처럼 개인에게 설명한다.
- Android 백그라운드·절전·단절 중에도 같은 규칙을 적용한다.
- 이미 잠긴 뒤 재접속하면 편집기가 아니라 잠긴 요약과 현재 단계로 간다.
- 마지막 10초는 숫자와 색, 마지막 5초는 허용된 한 번의 진동·짧은 음향을 보조로 쓸 수 있다.

## 12. 배신자 명령 단계

일반 명령이 양쪽 모두 잠긴 뒤 10초 배신자 단계로 간다. 이 패널은 통제하는 상대 팀 배신자 한 명에 대한 개인 비공개 화면이다.

표시 항목:

- 배신자 호출부호와 현재 공개 가능한 위치
- 명목상 소속 국장의 실제 일반 명령 중 규칙상 보이는 내용
- 현재 5×5 안에서 공개 가능한 동료 후보
- 남은 시간과 사용 가능 자금
- 도청 관련 공개와 `내 명령이 도청됨` 경고의 정확한 수신자

| 선택      |   비용 | 활성 조건                                     |
| --------- | -----: | --------------------------------------------- |
| 묵인      |     $0 | 항상                                          |
| 이동 실패 |     $0 | 실제 이동 명령이 있을 때                      |
| 공작 실패 |     $0 | 실제 해킹·암살·조사 명령이 있을 때            |
| 동료 암살 | $2,500 | 시작 시 보이는 5×5 동료 후보와 자금 조건 충족 |

동료 암살은 대상 선택 뒤 경고 확인을 거친다. 원래 이동·공작 실패와 실행 후에도 대상이 5×5 안에 있어야 함을 설명한다.

미확정 선택은 일반 명령처럼 계속 서버 draft로 저장하지 않는다. `배신자 명령 확정` 응답 뒤 잠그고, 10초 안에 확정하지 않거나 연결이 끊기면 서버가 `묵인`으로 처리한다. 현재 조종할 살아 있는 배신자가 없는 국장은 `MOLE_ORDER_OPEN` 진입 transaction에서 즉시 자동 확정되며 10초를 기다리지 않는다. 재접속 후 로컬 미확정 선택을 자동 제출하지 않는다.

## 13. 실행과 결과

### 13.1 명령 수행 단계와 실행 연출

- 서버가 확정한 사건 스트림만 재생한다.
- 배신자 명령 이후 별도의 `명령 수행` 단계에 들어가며 지도에서 이동 경로 보간, 암살·해킹·조사·숙청 동작과 교체 가능한 기본 도형 VFX를 실제 시간으로 재생한다.
- 카메라는 자동 회전하지 않는다.
- 공개되지 않는 실패 시도·공격자·배신 개입·숨은 위치를 연출로 암시하지 않는다.
- 실패 이동은 출발 셀 잔류와 개인 결과를 보여 준다.
- 애니메이션 건너뛰기 뒤에도 최종 상태와 보고서는 동일하다.
- 백그라운드 복귀 시 오래된 애니메이션 전부보다 최종 상태와 요약을 먼저 보인다.

### 13.2 우측 카드 결과와 5초 확인

1. 실행 cue가 시작되면 해당 자기 요원 또는 통제 배신자 카드에 현재 동작을 표시한다.
2. 성공·실패·취소는 같은 카드에서 즉시 갱신한다.
3. 모든 재생이 끝나면 별도 팝업 없이 카드 최종 결과와 `05` countdown을 5초간 유지한다.
4. 5초가 끝나면 진행 중인 경기는 다음 일반 명령으로 자동 전환한다. 승리·패배·무승부는 terminal 상태를 유지한다.

피해자는 암살로 제거된 사실만 받고 공격자·방식은 받지 않는다. 통제 배신자 제거, 재매수, 도청, 조사·명단 위치 효과와 목표 상태도 수신자 projection만 사용한다. 전체 canonical 사건 배열을 받은 뒤 UI에서 거르는 구현은 금지한다.

현재 로컬 훈련은 `reports.BLUE`와 판정 결과에서 BLUE 수신자에게 허용된 실행 cue만 구성한다. 숨은 상대 행동을 cue에 넣고 CSS로 숨기지 않는다. `같은 시드`와 `새 시드` 재시작은 우측 레일에서 제공하며, 같은 seed와 같은 명령은 같은 판정 결과를 만들어야 한다.

## 15. 접근성과 입력 품질

- 모든 핵심 버튼과 맵 대체 컨트롤은 최소 48×48 CSS px이다.
- 키보드 포커스는 2px 고대비 윤곽으로 항상 보인다.
- 숙청·전체 잠금·waiting/setup 작전 취소처럼 조작을 의도적으로 막는 modal만 포커스를 가두고 닫은 뒤 시작 컨트롤로 되돌린다. 지도 선택이 계속 필요한 명령 시트는 non-modal region으로 두며 포커스를 가두지 않는다.
- Escape는 미확정 하위 단계만 뒤로 가며 잠긴 명령을 취소하지 않는다.
- 버튼 이름에 대상과 동사를 포함한다. 예: `요원 H 이동 선택`, `C11을 목적지로 선택`.
- 아이콘 버튼에는 접근 가능한 이름과 터치에서도 여는 설명을 제공한다.
- Canvas에는 요약 설명과 동등한 자기 요원·도달 셀·행동 DOM 목록을 둔다.
- 팀, 선택, 위험, 성공을 텍스트·아이콘·선 패턴으로도 구분한다.
- 텍스트와 브라우저 200% 확대에서 주요 흐름을 완료할 수 있어야 한다.
- `prefers-reduced-motion`과 `prefers-contrast`를 존중한다.
- hover와 S Pen hover는 보조 수단일 뿐 기능 계약에 넣지 않는다.
- 모든 중요 음향 신호는 시각·텍스트로도 전달한다.

## 16. 컴포넌트와 구현 경계

Phase 0B에서 접근 가능한 UI primitive를 조합하되 시각 언어는 이 문서의 토큰으로 재정의한다. shadcn/ui를 사용한다면 다음 역할에 한정한다.

| 역할                    | 권장 primitive                     |
| ----------------------- | ---------------------------------- |
| 확인·위험               | AlertDialog                        |
| Tablet/Narrow 정보 레일 | Sheet                              |
| 설정·도움말             | Dialog                             |
| 명령 유형 전환          | Tabs 또는 명시적 segmented buttons |
| 스크롤 보고서           | ScrollArea                         |
| 임시 사건               | Toast/Sonner 계열                  |
| 버튼·필드·라벨          | Button, Input, Label               |
| hover 보조 설명         | Tooltip                            |

- 기본 카드 외형을 반복해 일반 SaaS 화면처럼 만들지 않는다.
- 게임 전용 `AgentCommandComposer`, `MapViewport`, `MissionRail`, `AgentRail`, `PhaseClock`, `RosterPlacement`, `EventReport`를 도메인 컴포넌트로 둔다.
- 명령 작성기는 흩어진 boolean이 아니라 식별 가능한 단계와 discriminated union으로 표현한다.
- 게임 규칙·경로 검증·비용 계산의 canonical 구현은 React, R3F와 분리된 deterministic Core에 둔다.
- 클라이언트 계산은 미리보기이며 서버가 저장·잠금·실행에서 다시 검사한다.
- Canvas 월드 좌표를 API에 보내지 않는다. `agent_id`, `cell_id`, 순서 있는 `path_cell_ids`, `action`, 공개 가능한 `target_id`를 사용한다.
- 숨은 canonical state를 브라우저로 보내 UI에서 숨기지 않는다.
- 폰트·색·간격·z-index·움직임은 단일 토큰 계층에서 관리한다.
- projection cache는 플레이어·게임별로 격리한다.
- 앱 스캐폴드와 UI 패키지, fixture 로비·HUD·Q-079 command composer, 가로 전용 app shell·세로 orientation gate, 전체 화면 지도·반투명 HUD와 pan·zoom 투명화, 지도 직접 명단 은닉부터 3D 명령 수행·우측 카드 결과·다음 턴·결정성 재판정까지의 로컬 fixture 플레이는 구현·로컬 검증됐다. 권위 서버 저장·두 클라이언트와 외부 서비스는 구현하지 않았으며 계속 보류한다.

## 17. 성능과 품질 예산

수치는 첫 구현의 목표이며 실제 Galaxy Tab S9+에서 측정해 조정한다. 측정 전에는 통과로 기록하지 않는다.

### 17.1 렌더링 목표

- 활성 조작 중 60fps 목표, 지속 하한 30fps
- 기본 장면 draw call 150 이하
- Tablet DPR 상한 초기값 1.5
- 후처리 없음
- 실시간 그림자 주광원 1개 이하, 품질 단계에서 끌 수 있음
- 맵 타일·건물은 인스턴싱 또는 병합 가능한 구조
- 요원 6명, 256 논리 셀과 기본 도형 건물을 기준 부하로 측정
- 카메라 정지 중 불필요한 매 프레임 React state 갱신 금지

프레임 p95가 25ms를 3초 이상 넘으면 그림자, 안티앨리어싱, DPR 순서로 품질을 낮춘다. 품질 변경은 규칙, hit target 또는 정보량을 바꾸지 않는다.

### 17.2 상호작용 목표

- 로컬 눌림·선택 피드백 100ms 이내
- 도달 범위·기본 경로 미리보기 50ms 이내
- 패널 전환 중 메인 스레드 100ms 이상 long task 없음
- 네트워크 저장 지연은 별도 측정하고 `저장 중`으로 표시
- 타이머는 deadline 재동기화 후 250ms 이내 오차 목표
- 배경 복귀 1초 안에 동기화 상태 표시, 응답 전 잠금 금지

### 17.3 자산 예산

- 첫 데모 3D 텍스처 압축 전송량 총 4MB 이하 목표
- 한 자산 실패가 전체 맵 상호작용을 막지 않음
- 미래 GLB/glTF는 지연 로드하고 대체 기본 도형 유지
- 실제 사용하는 폰트 굵기·문자 범위를 최적화하되 한글 글리프 누락을 검증

## 18. 구현 수용 기준

### 18.1 로비와 시작 준비

- 두 브라우저에서 방 생성·참가·준비·재접속을 완료한다.
- 팀 배정이 방장 선택과 무관하고 양쪽 projection이 서로 다름을 검증한다.
- 명단 배치에서 상대 후보가 payload와 화면에 노출되지 않는다.
- 같은 건물 선택 시 두 선택만 무효화되고 상대 위치는 공개되지 않는다.
- 다른 건물 선택 후 첫 일반 명령으로 전환한다.
- 초대 링크 응답 유실 시 재발급되고 이전 링크가 폐기된다.
- 초대 링크 60분·10분 경고·만료·재발급과 429 `Retry-After`가 server time 기준으로 동작한다.

### 18.2 명령 작성

- 요원 터치 후 `이동 / 대기 / 심문 / 숙청`이 먼저 열린다.
- 이동 후 도달 범위를 표시하고 지도 목적지를 직접 탭하면 빨간 대표 최단 경로와 `이동만 / 조사 / 암살 / 해킹`이 즉시 열린다.
- 요원과 도착 공작 명령판은 지도 좌표에 붙어 pan·zoom 때 함께 이동하며 별도 이동 팝업이 없다.
- 현재 셀을 선택해 0칸 공작을 만들 수 있다.
- K/H/D 모두 3칸, 상하좌우·단순 경로·시설 예외와 비용이 일치하며 F의 4칸 능력이 남아 있지 않다.
- 암살 대상, 해킹 시설, 숙청 횟수, 예산 초과가 이유와 함께 비활성화된다.
- 다른 요원으로 이동해도 저장된 초안이 유지된다.
- hover 없이 터치만으로 전체 흐름을 완료한다.
- 키보드와 DOM 대체 목록만으로 같은 명령을 완료한다.

### 18.3 저장과 동시성

- 완전 요원 초안마다 서버 저장 상태가 보인다.
- 미완성 경로·대상은 저장되지 않는다.
- 새로고침·Android 백그라운드 복귀 후 저장된 초안만 복원한다.
- draft 편집이 상대에게 잠금 상태나 revision 이벤트로 노출되지 않는다.
- 같은 계정 두 탭의 draft 충돌을 버전 오류로 감지한다.
- 서버의 수동 잠금 성공 뒤 편집이 불가능하다.
- 50초 시간초과는 저장된 완전 초안을 보존하고 나머지를 대기로 채운다.
- 10초 배신자 미확정은 묵인으로 처리된다.

### 18.4 비공개 정보

- RED/BLUE 두 클라이언트의 원시 응답에 상대 배신자, 숨은 목표, 비공개 경로·명령·확률·실패 시도가 포함되지 않는다.
- 도청, 조사, 명단 보유, 목표 운반, 드롭, 암살 피해가 정확한 기간과 수신자에게만 보인다.
- 숨긴 DOM, 로그, 접근성 이름, analytics payload에도 canonical 비밀이 없다.
- 상대의 정확한 잠금 시각과 편집 중 상태를 추정할 이벤트가 없다.

### 18.5 반응형·접근성

다음 가로 CSS 뷰포트에서 핵심 흐름을 검증한다.

- 1440×900
- 1280×800
- 1024×640

각 가로 뷰포트에서 패널 겹침, 잘린 확정 버튼, 이중 페이지 스크롤, 48px 미만 핵심 터치 대상과 색상만의 상태 구분이 없어야 한다. 800×1280, 768×1024와 360×800에서는 gameplay 핵심 흐름을 검증하지 않고 orientation gate가 Canvas·HUD·명령 입력을 차단하며 가로 회전을 안내하는지만 검증한다. 방향을 가로로 되돌리면 같은 fixture 상태로 복귀해야 한다. 데스크톱 에뮬레이션은 실기기 통과를 대체하지 않는다.

- 로컬 fixture의 absolute deadline은 interval tick 누적을 신뢰하지 않고 visibility·focus·pageshow마다 wall clock으로 남은 시간을 재계산한다. 이는 Android background throttling을 복구하는 로컬 harness이며, 11.4의 Production 서버 시각 권위를 대신하지 않는다.
- 로컬 브라우저 자동화로 고정 스폰·1칸 건물 도시, 로비→지도 직접 명단 은닉→`요원 선택 → 이동 → 지도 목적지 → 빨간 대표 경로 + 도착 공작` Q-079와 지도 연동 명령판 위치를 확인했다. 핵심 전체 흐름의 page exception·console error는 0건이며 R3F 9.7.0 호환 Three.js 0.182.0 고정 뒤 `THREE.Clock` deprecation warning도 0건이다.
- 전체 화면 지도, PC·태블릿 양쪽 rail, 허용되지 않은 상대 활동 숨김, 실시간·이전 턴 요원별 명령 성공/실패, 미완성 명령 잠금 방지, pan 중 HUD opacity `0.09`와 복귀, 드래그가 셀 탭으로 오인되지 않음도 회귀 통과했다.
- 이 결과는 브라우저 자동화·수동 로컬 fixture 범위다. 사용자는 PC와 태블릿의 현재 pointer·touch 입력 작동을 직접 확인했지만 정확한 Galaxy Tab S9+ 환경·S Pen·WebGL2·성능과 권위 서버·두 클라이언트 흐름은 아직 검증하지 않았다.
